## 🌏 国内

### 1. AI 模型推理 GPU 资源调度：256 卡集群利用率从 41% 提升至 73%
📰 CSDN 技术实践 | 2026-04-18 | https://blog.csdn.net/rbzheg_449/article/details/159792669

这项实践在 256 卡 H800 集群上承载 200 多个推理任务，组合使用动态批处理、优先级抢占和显存超分。公开数据给出：显存超分系数 1.3 时，P99 延迟劣化不超过 8%，GPU 利用率从 41% 提升到 73%，并配合 vLLM continuous batching 做参数调优。对线上推荐或 Agent 服务，价值不在单卡 benchmark，而在把排队、显存和任务优先级统一成调度问题。

### 2. Tool-Use Agent 的 RLHF 决策路径优化：ToolBench 32% 提升至 51%
📰 CSDN 技术实践 | 2026-06-08 | https://blog.csdn.net/2501_92132293/article/details/16112393

该实践把工具调用序列直接建模为动作空间，用 Action Chunking 压缩探索维度，并在奖励中同时计入任务完成度、工具成本与调用次数。其公开实验用 Reject Sampling 替代 PPO，在 5B Agent 的 ToolBench 上从 32% 提升到 51%。对企业 Agent 来说，这个方向提醒我们：奖励不能只看最终答对，还要约束调用路径长度、工具成本和失败恢复；这正是 Harness 层可观测、可审计的基础。

### 1. “The Attacker Moves Second”：LLM 安全评估必须引入自适应强攻击者
📰 OpenAI、Anthropic、Google 联合研究 | 2026-06-07 | https://blog.csdn.net/cf2suds8x8f0a/article/details/153283004

这项研究指出，静态测试集和固定攻击模板会高估防御效果；在通用自适应攻击框架下，论文评估的 12 类防御机制多数都被攻破，部分攻击成功率超过 90%。对企业 Agent 和 RAG 系统，安全闸门不能只做一次性离线测评，而应持续引入会观察防御反馈、再调整策略的攻击者，覆盖提示注入、工具越权和多轮诱导等真实路径。

### 2. Reasoning-targeted Jailbreak：针对推理模型思维链的越狱攻击
📰 天津大学团队 / arXiv 2604.15725 | 2026-06-07 | https://arxiv.org/abs/2604.15725

研究专门考察推理模型展开中间推理时的安全边界，使用语义触发与心理框架等方式，诱导模型在长链推理过程中暴露被隐藏的危险意图。它给生产系统的启示是：安全检查不能只放在最终答案层，也要对推理过程中的工具调用、外部检索、状态变化和高风险意图做分段监控。对于代码 Agent，尤其要把“生成—执行—验证”拆成可拦截、可回放的状态机。
